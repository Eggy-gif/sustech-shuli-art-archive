# 栗藏 · 树礼艺术资产馆

南方科技大学树礼书院学生会宣传部艺术资产收藏站。

以奶油黄、栗棕与金黄为视觉基调，收录小栗子、拟人化栗宝及 Q 版角色、节日与活动海报、宣传物料等创作。希望换届之后，作品仍有归处，作者仍被记住。

## 页面与功能

- **首页**：栗宝作品拼贴、精选作品与资产馆入口。
- **艺术资产页**：按年份、类别筛选，搜索作品标题、类别、作者及原文件名。
- **作品详情**：大图预览、上一件/下一件、下载展示图、跳转作者档案；支持 Esc 关闭。
- **创作者页**：创作者列表与每位作者的作品档案。
- **响应式布局**：适配桌面、平板与手机，支持减少动态效果的系统偏好。

## 当前收录状态

目前收录 31 张真实作品，使用本地 WebP 展示图。相似作品与不同版本均保留。

提供的原始文件以「资产 (编号).jpg」命名，未附年份及作者信息。因此，当前所有作品的年份标为「年份待补充」，作者归入「待补充署名」。标题与类别根据画面内容整理，并非原作者命名，后续可校正。

这是一个静态浏览网站，尚无后台管理、在线上传、账号登录或数据库。浏览器中操作筛选不会修改文件。仓库设为私有不代表部署后的网站自动具有访问控制；如需上线供部门内部使用，应另行配置访问权限。

## 本地预览

下载或克隆仓库后，直接用现代浏览器打开根目录的 `index.html`。无需安装 Node.js、前端依赖或执行构建。请保留关联脚本、样式和 `assets/` 目录。

页面使用哈希路由，可以直接定位到：

| 路由 | 页面 |
| --- | --- |
| `index.html#home` | 首页 |
| `index.html#archive` | 艺术资产馆 |
| `index.html#authors` | 创作者列表 |
| `index.html#author/uncredited` | 待补充署名的作品档案 |

网站运行不依赖在线图片服务或外部字体。

## 维护作品与作者

### 修改标题和类别

在 `data.js` 的 `window.archiveAssets` 数组中修改对应条目：

```js
[1, '花间 · 栗宝人物插画', '栗宝形象']
```

三个值分别为作品编号、标题、类别。类别按钮根据数据自动生成。同一类别请使用一致的名称。

### 补充作者

在 `window.archiveAuthors` 数组中添加作者，保留尚有作品关联的 `uncredited` 条目：

```js
{
  id: 'creator-01',
  name: '作者姓名',
  role: '2025 届宣传部 · 插画创作',
  bio: '作者确认后的个人简介。'
}
```

`id` 必须唯一，建议使用简短英文、数字与连字符。作品的 `authorId` 应引用这里已存在的作者 ID。当前数据模型每件作品关联一位作者，尚不支持多作者分别关联。

### 按作品填写年份与署名

当前 `.map(...)` 为所有作品设置 `year: null` 和 `authorId: 'uncredited'`。不要直接把它们整体改成某个年份或作者，否则会改变所有作品的归属。

可在 `data.js` 末尾追加逐件更新的代码。例如，以下示例只有在作者 `creator-01` 已添加、且第 1 件作品的资料确认无误后才使用：

```js
const asset = window.archiveAssets.find(item => item.id === 1);
Object.assign(asset, {
  year: 2025,
  authorId: 'creator-01'
});
```

保存并刷新页面后，会自动出现对应年份分组与作者作品列表。未知年份继续保留 `null`，不要用文件修改时间推断创作年份。建议部门统一约定年份表示创作年还是届次，避免混用。

### 新增作品

1. 将优化后的图片放入 `assets/`，例如 `art-32.webp`。
2. 在作品数组中、`.map(...)` 之前增加 `[32, '作品标题', '作品类别']`，确保编号不重复。
3. 如已确认年份和作者，按照上面的方式逐件补充信息。
4. 检查作品详情、分类、搜索与作者跳转。

现有映射会根据编号生成 `image` 与 `source`。如果文件名不符合 `art-编号.webp` 或原文件不是对应编号的 JPEG，请在映射后覆盖该作品的 `image`、`source` 字段。

首页精选作品由 `script.js` 中的 `[24, 2, 26, 7]` 编号列表控制；首页拼贴图片位于 `index.html`。新增或移除作品时，还需同步更新首页与侧栏中手动写入的「31」计数。资产列表与作者页的计数会自动更新。

## 图片处理与原稿保存

网站下载按钮提供的是优化后的 WebP 展示图，不是可编辑原稿。当前仓库不包含原始 JPEG、PSD、AI 等设计源文件，建议部门另行保存原稿、字体、印刷文件和授权说明。

`prepare_assets.py` 依赖 Python 与 Pillow；仅处理图片时才需要它们，浏览网站不需要 Python。首次在其他设备使用时，应先修改脚本中的 `source` 路径。脚本目前固定处理编号 1—31 的 JPEG，缩略总览布局也按这个数量设置；新增素材时需同步调整循环范围和总览尺寸。

```sh
python -m pip install Pillow
python prepare_assets.py
```

脚本会将图片最长边限制为 1600 像素，以 WebP 格式写入 `assets/`，并生成用于检查的 `contact-sheet.jpg`。再次执行会覆盖对应的展示图，请先确认来源正确。检查总览和测试截图已被 Git 忽略。

- 将原稿保存位置、仓库维护权限与署名资料一并交接。
- 修改后检查桌面和手机布局，以及搜索、筛选、详情、下载和作者跳转。
